# 06_HP

## 現行トップページ

- `index.html`: 1ページ完結型の公式ホームページ
- `tokens.css`: 色、文字、余白、角丸、動きの共通トークン
- `styles.css`: トップ、作品詳細、404の共通スタイル
- `games-data.js`: トップへ表示するゲーム作品データ
- `site.js`: 作品カードの描画とイラスト表示
- 主要ナビゲーションは `GAMES / ART / CREATOR` とし、外部リンクはCREATOR直下にまとめる。
- `assets/hero-desktop.jpg`: PC用HERO画像（2400 × 480px）
- `assets/hero-mobile.jpg`: 768px未満のスマートフォン用HERO画像（960 × 480px）
- `works/nene-flower-quest.html`: 作品詳細ページの初期例
- イラスト一覧の大型JPEGは400pxの軽量サムネイルを使い、元画像はライトボックスを開いた時だけ読み込む。元から小容量の素材はそのまま使う。
- ネネのキービジュアルは640px・1280px・2000pxを表示幅に合わせて配信する。
- OGPとcanonicalは `https://www.iwamycraft.com/` を正規URLとする。公開後のSNS上の実表示は未確認。

外部サービスへの導線はトップの `Links` に集約する。ゲームの公開先が未確定の間は実際の制作状況を非操作のテキストで示す。ネネは現在 `制作中`。

GitHub Pages で公開するホームページ用フォルダ。

## 素材ファイル名のルール

`assets/` 内の画像をページで利用する場合は、HTML/CSS から参照する前に用途が分かる名前へリネームする。

- 英小文字、数字、ハイフンを基本にする。
- `export`, `screenshot`, `IMG_0001`, `image` だけのような作業名は使わない。
- 日本語名や空白を含むファイル名は、公開ページで使う前に英語の説明名へ変える。
- 作品素材は `作品名-用途.png` の形に寄せる。例: `nene-flower-quest-title.png`
- キャラクターやUI素材は `対象-用途-種類.png` の形に寄せる。例: `iwamy-sho-walk-sprite.png`

## 作品ページの方針メモ

Iwamycraft のトップページはブランド入口として扱い、作品ごとの詳しい紹介は固有ページで扱う。

- 作品が公開段階に近づいたら、`works/nene-flower-quest.html` のような固有ページを追加する。
- 固有ページには、概要、スクリーンショット、ジャンル、プレイ時間、対応環境、あらすじ、キャラクター、公開先、クレジットを置く。
- ファミコンの説明書のような冊子イメージの画像を作る予定があるため、固有ページはその冊子ビジュアルを見せる場所としても設計する。
- トップページの作品一覧は、最新作から順に並べる入口に留める。

## 運用方針メモ

トップページは「Iwamycraft」という創作工房ブランドの入口として扱う。ゲーム販売ページや詳細な作品紹介ページに寄せすぎず、何を作っているブランドか、いま公開中または制作中の作品が何かを短く伝える。

作品ごとの詳しい情報は固有ページに集約する。`ネネは花を咲かせたい！` の固有ページは、任天堂ファミコンページのように、説明書を読む楽しさや作品世界に入る感覚を大事にする。特に MOTHER のような「小さな物語」「キャラクター」「遊び方」「世界の雰囲気」を読ませる方向を参考にする。

公開先リンクは、ゲームが公開できる段階で開通する。現時点では無理にトップから外部公開先へ誘導しない。itch.io、フリーム、BOOTH など複数の公開先がある場合は、固有ページ側に「遊べる場所」や「公開先」としてまとめ、トップは必要最小限の導線に留める。

英語対応はゲーム完成に合わせて進める。最初から全文翻訳を目指さず、まずはタイトル、短い説明、遊び方、公開先まわりから整える。

将来的には、固有ページと連動してファミコン説明書のような冊子ビジュアルを作る。冊子には、あらすじ、キャラクター、遊び方、画面の見方、アイテム、世界観メモなどを載せる想定。

ゲーム固有ページのデザインは、ヘッダーとフッターのみ Iwamycraft 共通のブランド要素として残し、それ以外の本文エリアは各ゲームのトンマナに合わせて大きく変えてよい。トップページはブランド全体の落ち着いた工房感を保ち、固有ページでは作品世界、色、質感、タイポグラフィ、説明書表現をゲームごとに展開する。

## 公開方法

このフォルダ自体を GitHub Pages 用リポジトリとして扱う。

Vault 全体は Git 管理しない。Git 操作はこの `06_HP` フォルダ内だけで行う。

GitHub 側では、リポジトリの `Settings` → `Pages` → `Build and deployment` を `GitHub Actions` にする。

## 注意

### 更新時の確認

- 画像を差し替えたら、同じ画像の派生も同時に更新する。イラストは `iwamycraft-character-illustration.jpg` と `iwamycraft-character-illustration-thumb.jpg`、ネネは `nene-flower-quest-key-visual.jpg` と `-640.jpg` / `-1280.jpg` を照合し、HTMLの寸法と `srcset` も確認する。派生版が元画像より重い場合は採用しない。
- 共有CSSを変更したら、`index.html`、`works/` 内の作品ページ、`404.html` と同じCSSを使う旧案ページの参照バージョンを揃える。トークンは各HTMLから一度だけ読み込む。
- ナビやセクションIDを変更したら、上記ページのリンク先も確認する。`404.html` は存在しない深いURLで表示されるため、独自ドメイン直下を基準にしたルート相対URLを使う。
- 作品状態を変更したら、`games-data.js`、トップのJavaScript無効時表示、作品詳細を照合する。
- コード上の参照確認とブラウザの表示確認を区別する。実表示は320 / 375 / 414 / 768pxとPC幅で確認し、未実施の場合は記録する。

### 公開対象

- 個人情報や制作途中の非公開メモは `06_HP` に入れない。
- 画像を使う場合は、このフォルダ内に置いてから公開対象にする。
- 外部サービスのリンクを追加・変更するときは、`index.html` の `Links` を更新する。
- ゲームの公開先が決まったら、各作品ページに公開先リンクを追加する。
